## Review Findings Fixed

- **`showModal` after `reply()`** — the rules "I agree" button would have thrown `InteractionAlreadyReplied` on every single new member, since question 1 is a modal. The handler now delegates straight to the prompter without replying
- **Mass lockout on first run** — reconciliation treats "no record" as "new member, apply unverified". Joining an established server would have stripped access from everyone. Fixed with the enable gate plus a grandfather cutoff stamped at enable time
- **`reconcile()` call missing `guildId`** — would not have compiled
- **`content: undefined`** in `/onboarding status` — a type error under `exactOptionalPropertyTypes`
- Tests excluded from typecheck; Vitest exiting 1 on an empty suite; the migrate idempotency test not actually testing idempotency; floating promises in event listeners; `q3` marking the questionnaire complete with a missing answer; mod commands silently updating zero rows for unknown members; `moduleResolution` `bundler` → `NodeNext`

## Decisions Made

- Configuration moved from environment variables to a `guild_config` table; only `DISCORD_TOKEN` and `DATABASE_PATH` remain in the environment
- Onboarding tables re-keyed on `(guild_id, user_id)` — same person in two servers gets independent records and answers
- A guild is completely inert until `/config enable`, which runs a live preflight and refuses with named problems
- Enabling stamps `grandfather_before`, permanently exempting everyone already in the server, and reports the count so the admin sees the blast radius is zero
- Slash commands register globally; optional `DEV_GUILD_ID` registers instantly for development
- `grantVerified` applies the role before stamping the database so a rejected API call stays retryable
